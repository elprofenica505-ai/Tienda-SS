# Prueba de carga base

La prueba se ejecuta con `node scripts/load-test.mjs`. Por defecto realiza 120 solicitudes concurrentes en lotes de hasta 20 contra `GET /api/health`, que es un smoke test seguro y no escribe datos.

El umbral de aceptación local es una tasa mínima de éxito de 99% y p95 menor o igual a 1 segundo. La prueba de producción o staging debe ejecutarse con el mismo script y registrar URL, commit, región, fecha UTC y resultado.

## Presupuesto operativo configurado

| Superficie | Límite actual |
|---|---:|
| Tenant autenticado, ventana 60 s | 1,000 solicitudes |
| Usuario autenticado, ventana 60 s | 300 solicitudes |
| Endpoint autenticado, ventana 60 s | 2,000 solicitudes |
| Composición IP/usuario/tenant, ventana 60 s | 100 solicitudes |
| API pública por IP, ventana 60 s | 60 solicitudes |
| API pública por tenant, ventana 60 s | 600 solicitudes |
| API pública por endpoint, ventana 60 s | 300 solicitudes |
| Página máxima de catálogo/inventario | 100 documentos |
| Importación CSV | 500 filas |

El límite de importación evita transacciones y escrituras excesivas. El límite de exportación mantiene la compatibilidad con el entitlement mensual existente. Si una prueba real de negocio muestra saturación, debe ajustarse el presupuesto con una nueva evidencia, no aumentando límites de forma indiscriminada.
